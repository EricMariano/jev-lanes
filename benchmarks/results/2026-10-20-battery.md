### What this does and does not show

- It shows that both adapters work end to end and which behaviors appear on these cases.
- It does not estimate accuracy, calibrate thresholds or show that the fallback improves decisions: the sample is tiny, hand-written, labeled by the maintainers and run once.

## 3. Observations on this run

Each point describes these 37 cases only; none is an estimate for your domain.

1. **TypeSafe confidence is close to saturated.** 31 of 37 cases scored at least 0.95, and
   every clear, out-of-scope and Portuguese case scored 0.96 or more. With thresholds of
   0.85 and 0.60, 34 of 37 cases stayed in the auto lane, so the llm and human lanes were
   rarely used. The thresholds are illustrative; this run says nothing about good values.
2. **Ambiguity between defensible routes was mostly not reflected in confidence.** Seven of
   the eight ambiguous cases stayed in the auto lane with confidence 0.88–0.99. Only
   case 13 ("money back, the order never arrived") was escalated (0.48). The 8/8 "accepted"
   figure is permissive by construction, because every defensible route counts; counting
   only the first-listed route gives 7/8.
3. **A catch-all `other` route absorbs vague input.** "Help.", "It doesn't work." and
   "Hello, I have a question." were routed to `other` at confidence 1.0. High confidence
   here means "clearly none of the named routes", not "the request is understood".
   Whether vague input should reach a person is a product decision; with an `other` route,
   confidence alone will not send it there. Only the multi-intent message (case 23) fell
   to 0.79.
4. **The fallback behaved differently exactly where it was never consulted.** It abstained
   on "It doesn't work." and on gibberish, both of which Jev had routed to `other` at 1.0,
   so the policy never asked it. Elsewhere it agreed with Jev on 33 of 34 answers.
5. **No evidence that the fallback improves decisions.** It decided one case (23, a
   multi-intent message with no right answer) and chose `billing`. This battery was not
   designed to show an improvement, and it does not.
6. **Prompt-injection probes.** The plain "ignore all previous instructions" case (36)
   was routed correctly by both. The case that closes the `<case>` tag (37) dropped Jev to
   0.84, and the fallback abstained, so it was escalated to a human. One case cannot tell
   whether the confidence drop is a signal or chance.
7. **Cost and latency.** Medians: TypeSafe 0.23 s, `gpt-5-nano` 2.21 s (max 5.25 s). Both
   ran sequentially from one machine, once.

### Before drawing conclusions

- Use real (anonymized) messages from the target domain, not hand-written ones.
- Have labels assigned by people who did not write the cases or see model outputs.
- Include harder boundaries and a realistic share of messy input; repeat runs, since the
  fallback is not deterministic.
- Tune the thresholds on one split and report on a held-out split (see
  `benchmarks/README.md`).
